Your first run

  1. Open the application

    Double-click Run Ikaros.cmd in this folder. Keep the complete folder together; the app needs the files inside bin and scenarios.

  2. Pick an example

    Choose a card on the left. The Circular orbit demo is a good first run. Use Browse scenario... to open a different scenario file.

  3. Choose the run settings

    Use the three fields to set the duration, integration step, and time between saved samples. The example's defaults are already filled in.

  4. Run the calculation

    Click Run simulation. Watch the progress display; Cancel stops the calculation if you want to change your settings.

  5. Explore and keep the results

    After completion, click Open 3D viewer. Click Open results folder to find the files saved automatically for that run.

Three starting points

Pioneer 11 at Saturn

The original ten-body encounter: the Sun, Saturn, seven moons, and Pioneer 11. Defaults cover 37 days, so allow more calculation time than for the demos.

Circular orbit demo

A small illustrative orbit for learning the viewer controls and comparing integration steps.

Many-body demo

A central body and twelve massless test particles. They feel the central body's gravity while exerting no gravity themselves.

What the three fields mean

FieldWhat it controls
Duration (days)How much simulated time to calculate. One day is 86,400 seconds.
Integration step (s)How far the calculation advances in each step. A smaller value does more work and can reduce numerical error.
Save every (s)How often a position is saved for the viewer and CSV. Smaller values give more display samples and use more memory.

A one-second integration step and an hourly save interval are different settings. Ikaros calculates the steps between saved positions. It also saves the starting state and final state.

Steps are shortened when needed to reach a saved time exactly. Keep the save interval the same when comparing integration-step values.

Read the 3D view

  • Rotate: drag over the plotting area.
  • Zoom: scroll over the plotting area.
  • Move through time: use Play/Pause, Previous, Next, Restart, or drag the time slider.
  • Choose a body: use the body list to focus the camera or show and hide bodies.
  • Change the frame: use the on-screen controls or shortcuts to select a reference body or return to a fixed frame.

Trails show only positions saved up to the displayed time. Moving backward removes later trail segments. Hidden bodies still affect the gravity calculation.

Markers are enlarged so you can see them; their sizes are not physical radii. Changing the camera does not change the calculation or the coordinate frame used in the CSV.

Your run is saved automatically

Each completed run gets its own folder under results. The folder name includes a UTC timestamp and a suffix if needed to keep names unique.

FileContents
trajectories.csvEach body's elapsed time, name, mass, position, and velocity at every saved sample. Open it in a spreadsheet or analysis program.
summary.txtThe run settings, calculation method, final states, and any available endpoint comparison.
scenario-used.txtThe scenario and settings actually used, including changes made in the launcher.

CSV values use kilograms, metres, metres per second, and seconds in the original input frame. An endpoint error is shown only when the reference describes the selected target at the same final time. Changing the duration to a different endpoint skips that comparison.

Both absolute and relative endpoint errors are errors: smaller is better. Relative error is unavailable if the target has travelled zero distance. Ignore a folder that still contains INCOMPLETE.txt; its export was interrupted or failed.

Use your own bodies

Click Edit scenario file to open the selected file in your text editor. Add or remove body rows, change settings, and save. Return to Ikaros and click Reload file. You can also browse to another .txt file.

Body count comes from the rows in the scenario. You do not need to edit or rebuild C++ to change it. Give each body a unique name and use that name for camera focus, reference, and target settings.

Units, metadata, and file format

Each body row contains name,mass_kg,x_m,y_m,z_m,vx_m_s,vy_m_s,vz_m_s. Scientific notation is accepted. Zero mass creates a test particle. Quote names containing commas.

All starting positions and velocities must share a coordinate origin, axes, starting instant, and time scale. Changing an epoch or frame label does not transform coordinates. The supplied Pioneer vectors reproduce matching Horizons queries using the Solar System barycenter, the J2000 ecliptic plane, geometric states, and midnight TDB epochs. See the starting-data record for saved queries and headers.

What calculation is being preserved?

This version keeps the original point-mass force law, gravitational constant, and velocity-first update with position calculated from the average old/new velocity. The Pioneer starting states and masses are preserved.

Velocity-Verlet and Saturn's J2 gravity term have not been added. The model also omits propulsion, radiation pressure, relativity, extended-body gravity, and impacts. Smaller steps cannot repair missing physics or mismatched starting data.
